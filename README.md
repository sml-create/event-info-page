# TikTok投稿イベントのご案内

グリーンを基調とした、スマートフォン対応の静的Webページです。公開用は `index.html`、見た目を確認して編集する専用ツールは `editor.html` です。ログイン・データベース・サーバー起動は不要です。編集ツールだけJavaScriptを使用します。

**内容はサンプルです。日程・ハッシュタグ・参加条件・特典・審査方法・公式アカウント・問い合わせ先を確定してから公開してください。**

## 1. PCで表示を確認する（公開されません）

1. https://github.com/sml-create/event-info-page/tree/event-page-draft を開きます。
2. 緑色の「Code」→「Download ZIP」をクリックします。
3. ダウンロードしたZIPを展開します。Windowsは右クリック→「すべて展開」、MacはZIPをダブルクリックします。
4. 展開したフォルダの `index.html` をダブルクリックします。

新しく展開したフォルダのファイルを開いてください。Pythonやサーバーの起動は不要です。GitHub上でHTMLをクリックするとコードが表示されるため、見た目の確認はダウンロードしたファイルで行います。

## 2. コードを書かずに編集する

1. ダウンロードしたZIPを展開し、**`editor.html` をダブルクリック**します。
2. 「編集モード」で、点線の付いた文章をクリックして直接入力します。イベント名、説明文、見出し、日程、参加方法、条件、特典、審査方法、注意事項を編集できます。
3. Enterで改行できます。箇条書きは各項目の文章を書き換えてください。文章の貼り付けは書式なしで行われます。項目の追加やリンク先URLの変更はこの簡易ツールの対象外です。
4. 「表示幅」で「スマートフォン」を選ぶと、390px幅のデザインを確認できます。実機の完全な再現ではないため、公開前は実際のスマートフォンでも確認してください。
5. 「プレビューモード」で点線が消え、公開用と同じ見た目になります。「編集モード」で編集に戻れます。
6. **「公開用HTMLをダウンロード」**をクリックします。ブラウザのダウンロード先に保存された `index.html` を開いて確認してください。同名ファイルがある場合は `index (1).html` などになることがあるため、公開時は `index.html` に変更します。
7. 続きの編集に備え、**「編集用コピーを保存」**もクリックします。保存された `editor.html` を次回開けば、その文章から再開できます。別のPCに渡す場合も、この編集用コピーを渡してください。

自動保存やPC間の自動同期はありません。公開用HTMLは編集用コピーに自動で戻りません。必ず編集用コピーも保存し、次回は新しいコピーを開いてください。ダウンロードを許可するよう表示された場合は許可し、ファイルが保存されたことを確認してください。

日程・企業名・タグなどは複数箇所にあるため、それぞれ編集してください。装飾イラストは編集対象外です。

### 公開用ファイルをGitHubに反映する

1. 作業用ブランチ https://github.com/sml-create/event-info-page/tree/event-page-draft を開きます。
2. 「Add file」→「Upload files」をクリックします。
3. ダウンロードした公開用 **`index.html`** をアップロードします。
4. 作業用ブランチへ「Commit changes」で保存します。
5. 公開済みの場合は、確認後に `main` へ統合するとPagesに反映します。次の手順を参照してください。

`editor.html` は配布用のツールで、認証・共有保存・公開サイトの自動更新機能はありません。第三者が編集ツールを使っても、GitHubへの書き込み権限がなければサイトは更新できません。編集ツールには非公開情報を入れないでください。Pagesは公開元ブランチのファイルを配信するため、編集ツールをWeb上へ置きたくない場合は `main` に取り込む前に `editor.html` を公開元から除外し、PCにだけ保持してください。通常の閲覧用 `index.html` には編集ボタンは表示しません。

## 3. 公開前に確認する

- イベント名・日程・投稿締切・指定タグを正式なものに変更する。
- 参加条件・特典の種類と人数・金額・入賞連絡方法を確定する。
- 主催者名・公式TikTokアカウントのURL・問い合わせ先・個人情報の取り扱いを記載する。
- 「サンプル」「仮」「準備中」「応募は受け付けていません」などの表示を、実際の状態に合わせて更新する。
- PC・スマートフォンで文章とリンクを確認する。

ページに表示する情報はインターネットに公開されます。非公開情報や参加者の個人情報は書かないでください。`noindex` を指定していますが、検索結果への非掲載や閲覧者の制限を保証するものではありません。

## 4. GitHub Pagesで無料公開する（公開すると決めたときだけ）

GitHub Freeでは通常、公開リポジトリでGitHub Pagesを無料利用できます。非公開リポジトリはプランにより利用条件が異なります。Pages設定が利用できない場合は、契約・組織ポリシーを確認してください。ソースコードを公開してよいか判断する前に、リポジトリを公開へ変更しないでください。

1. 作業用ブランチで内容を確認します。
2. GitHubで https://github.com/sml-create/event-info-page/compare/main...event-page-draft を開きます。
3. 「Create pull request」をクリックし、次の画面でも「Create pull request」をクリックします。これは作業用ブランチの変更を `main` に取り込む依頼です。
4. 変更内容を確認して「Merge pull request」→「Confirm merge」をクリックします。権限や保護ルールによっては管理者の操作が必要です。
5. リポジトリ上部の「Settings」→ 左側の「Pages」をクリックします。
6. 「Build and deployment」の「Source」で「Deploy from a branch」を選びます。
7. 「Branch」を `main`、フォルダを `/ (root)` にして「Save」をクリックします。
8. 数分待ち、Pages画面に表示される「Visit site」または公開URLをクリックします。処理中・失敗の場合は「Actions」タブで「pages build and deployment」の結果を確認します。
9. 公開URLで表示とリンクを確認した後、そのURLをメルマガに掲載します。

通常のURLは `https://sml-create.github.io/event-info-page/` です。これは想定値で、まだ公開・動作確認していません。必ずPages画面に表示される実際のURLを使用してください。独自ドメインの購入は不要です。

既にPagesが有効なリポジトリでは、`main` への統合だけで更新が公開されることがあります。公開の準備ができるまでは統合しないでください。

## 5. 公開後に文章を更新する

保存した最新の編集用コピーを開いて修正し、新しい公開用HTMLと編集用コピーをダウンロードします。公開用 `index.html` をGitHubへアップロードし、公開元の `main` に反映すると数分後に自動更新されます。

事前確認したい変更は `event-page-draft` で編集し、ダウンロードして確認した後、手順4と同様に `main` へ統合してください。作業用ブランチの保存だけでは、`main` を公開元にしたPagesへ反映されません。

## 確認した範囲

JavaScript無効・オフラインでHTMLをブラウザに直接渡し、PC・スマートフォンのレイアウト、6つの案内セクション、ページ内リンク、外部リソースが不要なことを確認しました。この環境は管理ポリシーで `file://` が禁止されているため、ダブルクリック操作そのものは未検証です。GitHub Pages上での公開検証は実施していません。

編集ツールでは直接編集・改行・プレビュー切替・390px表示・公開用HTMLの出力・編集用コピーからの再編集を確認しました。公開用出力に編集用スクリプトや編集属性が含まれないことも確認しました。
